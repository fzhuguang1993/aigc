# 录屏字幕生成与烧录

给录屏成品自动**转写口播 → 生成字幕 →（可选）烧录进画面**。
纯逻辑模块，被三处界面复用：

- **工具中心「🎙 语音识别」**：语音识别主体工具，直接选视频 → 转写 → 存 TXT/SRT / 烧录（见「语音识别」说明）。
- **屏幕录制面板**：录完「顺带生成字幕」，产物紧跟成片。
- **任务中心**：勾选成品行 →「🔤 字幕处理」批量跑，可先检测是否已有字幕。

> 转写本体统一来自语音识别主体包 `video_text_tools/asr/`（原散在 `breakdown/` 的识别已抽出）。

> 一期范围：ASS 内联颜色烧录 + 纯文本 `.srt` 兜底 + 卖点语义高亮 + 抽帧检测。
> **不产出剪映草稿工程文件**（版本脆弱），需要精修就导出 `.ass/.srt` 再进剪映。

---

## 🎯 设计取向

- **纯逻辑、无 Qt**：`video_text_tools/subtitle/` 全部走回调（`log / progress / should_stop`），
  两处 UI 只是薄接线，不重复实现。
- **失败不静默**：逐文件落一条 `SubtitleResult(ok, message)`，整批不中断，末尾汇总「成功 X / 共 N」。
- **永不毁原片**：烧录写**新文件** `<stem>_字幕.mp4`；录屏的旁路 WAV 原样保留、绝不被覆写或删除
  （转写前先把旁路 WAV **复制**成临时副本再喂 Whisper，规避 `transcribe` 删同名 wav 的副作用）。
- **零新增重依赖**：Whisper 走既有可选包 `requirements-breakdown.txt`，烧录用既有 ffmpeg，
  **不改打包 spec**。

## 🖥 界面用法

### 入口一：屏幕录制「顺带生成字幕」

1. 「屏幕录制」→「保存位置」卡里勾选 **☑ 录完顺带生成字幕**。
2. 想调样式/烧录/高亮，点旁边 **⚙ 字幕选项** 预设（不点就用默认：只出 `.srt/.ass`，不烧录）。
3. 正常录制、停止。录制收尾会拿着成片路径 + 旁路录音，后台起一个字幕任务：
   - 默认**只出字幕文件**，不烧录（避免录完弹框打断），成片旁多出 `.srt`/`.ass`。
   - 进度与结果打在录制面板日志区。

### 入口二：任务中心「🔤 字幕处理」批量

1. 在成品列表**勾选**要处理的行（可多选）。
2. 点工具栏 **🔤 字幕处理**。没勾选会提示先选。
3. 选项框默认勾上 **检测已有字幕**：已烧过字幕的会自动跳过，不重复烧。
4. 执行中「字幕处理中 N 个…」，结束汇总「已生成 / 已跳过(含字幕) / 失败」，
   失败逐条列出原因（不静默）。

### 字幕选项框一览

| 项 | 说明 |
|----|------|
| 模型 | `medium` / `small` / `base` / `tiny`，越低越快越不准；**默认选中已就绪的最佳档**（不再默认未下载的 medium） |
| 模型状态 + ⬇下载模型 | 实时显示是否就绪；「🎙 语音识别」工具里可**就地下载**（进度走悬浮球，无需去别处），也支持**用国内镜像** |
| ☑ 检测已有字幕 | 抽帧问豆包「底部是否已有字幕」，命中则跳过 |
| ☑ 生成 SRT | 输出纯文本 `.srt`（兜底/给剪映用），默认勾选 |
| ☐ 保存逐字稿 TXT | 另存一行一句的纯文字稿 `<stem>.txt`（`SubtitleOptions.save_txt`，默认关） |
| ☐ DeepSeek 语义纠错 | 识别后把逐字稿送 DeepSeek 改同音字/错别字再落字幕（`asr_fix`，默认关；未配置则不启用） |
| ☐ 卖点高亮 | 命中卖点词的行用高亮色上色（**需配置豆包**，见下） |
| ☐ 烧录成片 | 把字幕烧进画面生成 `<stem>_字幕.mp4`（需 ffmpeg 带 libass） |
| 样式 | 字号 / 底部·顶部 / 前景色 / 描边色 / 高亮色 / 输出目录 |

## 🗣 Whisper 缺失怎么办（打包形态决定体验）

字幕靠 Whisper 转写。**Whisper 分两块：① faster-whisper 库（编译型大件）② 模型（运行时可下）**。
「库在不在包里」由打包决定，所以本项目出**两个 GUI exe**：

| 包 | 含库? | 字幕/拆解 | 用户要不要 Python |
|----|:----:|----------|:----:|
| **AIGC视频助手-创作版.exe** | ✅ 内置 | 点「⬇ 下载模型」自动下好即用 | **不用**（推荐发给要用字幕的同事） |
| **AIGC视频助手.exe**（精简版） | ❌ 剪掉(守 <300MB) | 点了会提示「请改用创作版」 | 不用（也无需用 pip） |

> 目标体验：**用户拿到「创作版」，点一下「⬇ 下载模型」就自动配好**——库随包走，
> 只有模型在你首次点击时下载（可勾「用国内镜像」走 `hf-mirror.com`），全程无需 Python/pip。

### 情形 A：没装库（`DepMissing`）——只会发生在精简版 / 开发版

- **精简版用户**：界面会直接说「请改用【创作版.exe】」，不给你 pip（你也装不了）。
  找维护人要创作版即可。
- **开发版(源码跑，本机有 Python)**：点引导里的「复制安装命令」，在工程目录执行
  ```
  pip install -r requirements-breakdown.txt
  ```
  （会拉进 ctranslate2 / av / tokenizers 等大件；这也是打「创作版」的前置。）

### 情形 B：没下模型（`ModelNotReady`）——库已在，只差模型

- 点选项框里的 **⬇ 下载模型**，下载慢/连不上就勾 **用国内镜像**（走 `hf-mirror.com`）。
- 模型落在 `%APPDATA%\AIGC视频助手\models`（目录名 `models--Systran--faster-whisper-<size>`）。
- 也可**手动放置**：把官方模型文件放进上述目录，检测到 `config.json` + blobs 即算就绪。

> 与「爆款拆解」共用同一套 Whisper 依赖与模型目录——创作版里两处都能用，模型下一次两处共享。

### 排障：勾了「用国内镜像」还是 `connectError`？

早期版本有两层问题：
1. **镜像设晚了**：镜像端点是在 `faster_whisper` 导入**之后**才设的，而 huggingface_hub 的
   `ENDPOINT` 在导入那一刻就按环境变量定死了——勾选镜像不生效，仍在连官方 `huggingface.co`。
2. **单端点一挂到底**：只试一个源，失败就直接报错。

现已改为**多端点自动兜底**（`transcribe.download_model`）：
- 导入前就先切好端点（环境变量 + `huggingface_hub.constants.ENDPOINT` 两管齐下）；
- 勾选镜像→依序试 `[hf-mirror, 官方]`；未勾→依序试 `[官方, hf-mirror]`；
- 某个端点连不上自动换下一个，每个端点的尝试/失败都实时打到日志。

**升级到本版并重启程序**后重试即可（旧进程里端点可能已定格）。若两个端点都不通（真·网络问题），
按上面“手动放置模型”兜底。

### 维护人：怎么出「创作版」

`build.bat` 一次出三个产物（精简 GUI / 创作 GUI / 命令行）：
- 创作版会 `--collect-all=ctranslate2 --collect-all=faster_whisper` 把库打进去；
- 若打包机 `.venv` 未装 faster-whisper，脚本会**自动跳过创作版**并提示先装依赖。

## ✨ 卖点高亮 & 抽帧检测（都以豆包为引擎）

两者复用「爆款拆解」的豆包 Vision 配置（`config.json` 的 `doubao` 段），无新增凭证。

- **卖点高亮**：把全字幕文本交给豆包，返回「卖点/强调词」表，命中词在 ASS 里包
  `{\c&HBBGGRR&}…{\c}` 内联上色（默认高亮黄 `#FFD400`）。
  **未配置豆包 → 高亮自动关闭，出普通字幕**（不报错）。
- **抽帧检测**：均匀取 3–5 帧问豆包「画面底部是否已有烧录中文字幕」，多数投票。
  用于「这批视频是不是已经带字幕了」，命中就跳过、避免重复烧。
  **未配置豆包 → 跳过检测**；调用失败 → 记「检测失败」。

> ⚠ 诚实说明：检测「是否已有字幕」依赖视觉大模型判断，**结果非 100% 可靠**。
> 判断为「未知」时，程序**保守当作没有字幕、继续补生成**（宁可多生成也不漏），不阻断流程。

## 🔥 烧录成片与 libass

- 烧录 = 用 ffmpeg 的 `ass` 滤镜把 `.ass` 字幕渲染进画面：**依赖 ffmpeg 编译了 libass**。
  主流构建都自带；启动前会探测 `ffmpeg -filters`，**缺 libass 时不烧录、只出字幕文件**，
  并给出「当前 ffmpeg 不含 libass，无法烧录，仅出字幕文件」的明确提示。
- ASS 里前景/描边/高亮色都用**内联颜色**表达，逐词上色不依赖外部字体样式文件。
- 产物 `<stem>_字幕.mp4` 写在输出目录（默认与源视频同目录），**不覆盖原片**。

## 📦 输出文件

| 文件 | 何时产生 | 说明 |
|------|----------|------|
| `<stem>.srt` | 勾「生成 SRT」 | 纯文本字幕，兜底 / 给剪映导入 |
| `<stem>.ass` | 总是（内部渲染源） | 带样式与卖点高亮的特效字幕 |
| `<stem>_字幕.mp4` | 勾「烧录成片」且有 libass | 字幕已烧进画面的新成片 |

**剪映衔接建议**：要二次精修（改词/调时间轴/换样式），直接拿导出的 `.ass` 或 `.srt`
拖进剪映，比烧录后再抠字方便得多——这也是「一期不产剪映草稿工程」的原因。

## 🗂 代码结构

```
video_text_tools/subtitle/
  models.py     SubtitleStyle / SubtitleOptions / SubtitleResult + 异常
  audio.py      find_sidecar / resolve_audio_source（旁路 WAV 复制成临时副本，护源）
  srt.py        write_srt（正文复用 asr.transcribe.to_srt）
  ass.py        build_ass / write_ass（样式头 + 逐段事件 + 卖点内联上色 + 转义）
  burn.py       ffmpeg_has_ass 探测 + _ass_filter 转义 + build_subtitle_command + run_burn
  detect.py     has_burned_subtitle（抽帧问豆包，未知→当作无字幕）
  highlight.py  pick_terms（豆包挑卖点词，未配置→[]）
  engine.py     run_one / run_batch（编排、逐条容错、进度回报）
  __init__.py   re-export 对外接口
```

- 配置：`core/config.py` 的「19. 录屏字幕」段，`subtitle_config()` 深合并默认样式。
- GUI 复用件：`gui/dialogs_subtitle.py`（`SubtitleOptionsDialog` / `ask_subtitle_options` /
  `whisper_missing_guidance` / `run_subtitle`）。
- 接线：`gui/dialogs_recorder.py`（录制面板）、`gui/pages_tasks.py`（任务中心批量）。
- 转写/模型来自语音识别主体包：`video_text_tools/asr/`（`transcribe` 转写与模型管理、
  `fixer.apply_fix` 语义纠错）；豆包复用 `breakdown/vision.py`（画面）、`breakdown/frames.py`（抽帧）、
  `ffmpeg_utils`（命令执行与能力探测）。
