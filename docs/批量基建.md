# 批量基建（抖音本地推 · 账户搭计划）

把「计划方案 × 本地推账户」铺成矩阵，自动完成 **素材上传 → 创建项目 → 创建营销**。
入口是左侧导航的独立页「🏗 批量基建」（二期升级后不再挂在「工具中心」卡片里）。

> 一期范围：**抖音本地推官方 OpenAPI（OAuth2.0）参考实现**。
> 端点真实值后期在 `config.json` 的 `local_push` 段（或账号 `extra`）回填即可，不必改代码。
>
> 二期升级：新增**三级组织管理（客户 › 执照/主体 › 账户）**，本地推账户从
> `config.json` 迁入 SQLite，并与员工「组织结构」的数据权限打通。

## 🎯 设计取向

- **官方开放平台直连**：走巨量引擎开放平台「本地推投放能力」，账户用官方 OAuth
  `access_token` 鉴权（请求 query 携带），不借助任何中间服务器。
- **凭证本地加密**：Access Token / Refresh Token 以「使用人姓名」为密钥用 Fernet 加密，
  存本机 SQLite `local_ad_accounts.secret_enc`，**盘上不留明文、不上传服务器**。
  （沿用 `material_extract` 的 `encrypt_value/decrypt_value`，与一键发布同一套加密逻辑。
  老版本存 `config.json` 的 `local_accounts` 首次访问时一次性幂等迁入 DB。）
- **计划方案模板**：项目/营销层参数（预算/出价/定向/门店或商品）+ 素材清单存成
  可复用的「方案」，执行时按 方案 × 账户 批量下发，同类门店一条方案覆盖一组账户。
- **端点全配置化**：所有接口地址、附加请求头从配置读，代码不硬编码——平台改版时改
  配置即可。
- **失败不静默**：单格异常/端点未配置都落成 `ok=False` 的执行记录并写日志，
  绝不中断整批、绝不假成功。

> ⚠ 平台账号是使用者自有凭证，账号管理**不套维护人口令**（区别于素材提取的接口密钥）。

## 🧱 本地推层级（新版）

```
广告主账户（advertiser_id）
  └─ 项目（project）       预算 / 出价 / 定向（地域/年龄/性别/时段）
       └─ 营销（marketing） 推广门店或商品 / 投放抖音号 / 绑定素材
            └─ 素材（video） 视频文件上传 → video_id，标题文案
```

一次搭建 = 在账户下按方案创建 1 个项目 + 1 个营销，营销绑定该方案的全部素材。
旧版「单元/创意」口径不适用，不要按旧文档对字段。

## 🏛 三级组织管理（客户 › 执照/主体 › 账户）

投放账户按商业归属组织成一棵**严格树**（一个账户只归一张执照、一张执照只归一个客户）：

```
客户（local_customers）        一个广告主品牌/连锁，可挂多张执照
  └─ 执照/主体（local_licenses） 对应一张营业执照主体（主体名/统一社会信用代码）
       └─ 本地推账户（local_ad_accounts） 叶子，凭证加密存 secret_enc
```

### 层级 + 逐个混合授权（就近继承）

三层都带一个 `owner`（负责成员名，值域对齐员工「组织结构」的成员名）。解析一个账户的
**有效负责人**按**就近继承**：账户 `owner` → 所属执照 `owner` → 所属客户 `owner`，取第一个非空。
于是两种授权方式并存：

- **层级授权**：在客户（或执照）上设一个 `owner`，其下未单独指定的账户自动继承；
- **逐个授权**：给单个账户直接设 `owner`，覆盖上级。

### 与员工「组织结构」的关系（数据权限打通）

复用 `store/org_store.py` 的角色语义 `visible_owners()`：

| 会话 | 可见范围 |
|------|----------|
| 未启用组织（单机）/ 未登录 / admin | 三级全可见、不限 |
| member | 只看**有效负责人＝自己**的账户；其所在客户/执照若无可视账户则整节点隐藏 |
| manager | 看**本部门 active 成员**（含自己）负责的并集 |

单机模式下授权列可留空不强制，三级全可见。

## 🖥 界面用法（独立页 · 四个分层 Tab + 面包屑）

页顶一条面包屑随下钻实时更新（如 `全部客户 › 某客户 › 某执照`），四个 Tab 标题带序号体现层级：

1. **① 客户**：客户表（名称 / 负责成员 / 执照数 / 账户数），＋新建 / ✎编辑 / 🗑删除；
   编辑框含名称、备注、负责成员下拉（单机隐藏）。点「⤵ 下钻」把执照/账户页过滤到该客户。
2. **② 执照**：按当前选中客户过滤的执照表（名称 / 主体说明 / 负责成员 / 账户数）；
   负责成员留空＝继承客户。
3. **③ 账户**：按当前客户›执照下钻过滤的账户表（别名 / 归属 / 账户ID / 负责成员 / 授权状态），
   ＋添加 / ✎编辑 / 🗑删除 / 🔄刷新 / 🔌检测授权；添加/编辑弹「本地推账户」框，含
   **归属执照**下拉（从执照页下钻进入时默认落在当前执照）与**负责成员**下拉（留空＝继承）。
   检测授权对当前范围账户跑 `check_auth` 回填授权状态列。
4. **④ 批量搭建**：账户勾选（来源＝已按下钻+权限过滤的可见账户）、计划方案表
   （＋新建 / ✎编辑 / 🗑删除，方案模板存本机）、日志区与「▶ 开始搭建」，
   以及**执行历史 · 分层统计**（按客户/执照/账户切换）。勾选账户与方案 →
   二次确认「N 个账户 × M 个方案，共 N×M 次」→ 执行，结果逐条打印并写 `local_build_runs`。

## ⚙️ 端点配置（`config.json` 的 `local_push` 段）

抖音本地推的可变项**全部从配置读，代码不硬编码**。
默认见 `core/config.py` 的 `LOCAL_PUSH_DEFAULTS["douyin"]`：

| 键 | 含义 | 留空/占位时 |
|----|------|-------------|
| `api_base` | 开放平台基址，默认 `https://open.oceanengine.com` | 有默认值 |
| `advertiser_info_url` | 授权校验（查询广告主信息） | 空则 `check_auth` 跳过在线校验、不阻断搭建 |
| `asset_upload_url` | 素材上传（POST 视频 → `video_id`） | 空则搭建时抛「未配置」，不漏建 |
| `project_create_url` | 创建项目（预算/出价/定向） | 同上 |
| `marketing_create_url` | 创建营销（绑定素材/门店或商品） | 同上 |
| `headers` | 附加请求头（缺省只带 `access_token` query 参数） | 缺省为空 |

> 各端点可配**相对路径**（自动拼 `api_base`），也可配整段绝对地址。
> 账号级可用 `extra` 覆盖以上任意键（`extra` 合并优先于全局默认），
> 便于不同账号走不同端点/网关。

## ⚠ 风险与诚实说明

开放平台接口路径与字段名以官方《本地推投放能力》文档为准。本实现把
**标准执行序列**（授权校验 → 素材上传 → 创建项目 → 创建营销）与**可配置端点**
都铺好了，但**不承诺任何时点都能无条件跑通**：

- 若某端路径或字段与官方版本不符，请在账号 `extra` / `config.json` 里覆盖端点，
  或按官方文档微调 `video_text_tools/local_push/douyin.py` 的 payload 映射；
- 端点未配置（留空或占位 `<...>`）时会明确抛「XX端点未配置」并落失败记录，
  **而不是假装成功**。

## 🗂 代码结构

```
video_text_tools/local_push/
  models.py    平台/推广口径常量 / LocalAccount（带 license_id/customer_id/owner）
               / PlanItem / BuildRecord（带三个组织列）/ apply_org_fields / 异常层级
  base.py      BuildAdapter 契约 + 注册表（register/get_adapter）+ run_one 兜底异常
               （回行统一调 apply_org_fields 回填组织维度）
  douyin.py    抖音本地推参考实现（OpenAPI/OAuth2.0，端点全走配置）
  accounts.py  账户读写门面（委托 store.local_org_store；首次读取触发 config→DB 迁移）
  plans.py     计划方案模板读写门面（明文 config 段）
  runner.py    build_batch：方案 × 账户 矩阵、单格容错、进度回报

store/
  local_org_store.py  三级组织核心：客户/执照/账户 CRUD + 级联删除 + 凭证加解密
                      + effective_owner 就近继承 + visible_filter + config→DB 幂等迁移
  build_store.py      执行历史入库：record 落三组织列 + recent 按维度过滤 + stats_by_level
  org_store.py        抽出 visible_owners()，与三级组织共用角色语义
```

- 凭证与三级组织读写：`store/local_org_store.py`（加密沿用 `material_extract` 的
  `encrypt_value/decrypt_value`，盐=姓名，前缀 `enc:v1:`）；端点仍读 `core/config.py` 的
  `local_push_config`，计划方案仍走 `list_local_plans / save_local_plan / delete_local_plan`。
  （`core/config.py` 的 `list_local_accounts / save_local_account / delete_local_account` 已
  deprecated，仅作一次性迁移源保留。）
- 界面：`gui/pages_local_build.py`（`LocalBuildPage` 独立页，页栈索引 13）复用
  `gui/dialogs_build.py` 的 `LocalAccountDialog`（已扩展归属执照/负责成员）与 `PlanDialog`；
  搭建逻辑已从原 `BuildPanel` 迁入本页第四个 Tab。入口下线：`pages_tools.py` 的 `TOOLS`
  与 `tool_panels.py` 的 `PANEL_FACTORIES` 不再含「批量基建」。

## 📜 执行历史在哪看

每次「方案 × 账户」的结果行都写入 SQLite `local_build_runs` 表
（`store/build_store.py`：`record/record_all/recent/stats/stats_by_level`）：
字段除 `platform / account / advertiser_id / plan_name / ok / project_id /
marketing_id / asset_count / message / created_at` 外，还带三个组织列
`customer_id / license_id / account_id`（老库首次升级时自动 `ALTER` 补列）。
`recent(...)` 可按 `customer_id/license_id/account_id` 过滤回读，`stats_by_level(level)`
按客户/执照/账户分组聚合 total/ok/fail（LEFT JOIN 组织表取名）。界面上在「④ 批量搭建」
Tab 的“执行历史 · 分层统计”区展示；历史明细可随时从该表回读。
