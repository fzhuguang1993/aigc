# 云端任务状态查询功能更新

## ✅ 功能已实现

`status` 命令现在会**实时从云端查询**每个任务的最新状态，而不是只显示本地缓存的信息。

## 🔄 工作原理

### 之前的行为
- 显示本地注册表 `REG.active()` 中的状态
- 状态只在轮询线程每 5 秒更新一次
- 可能存在延迟

### 现在的行为
- **每次执行 `s` 或 `status` 命令时，实时查询云端 API**
- 自动同步云端状态到本地注册表
- 显示最新的任务进度和状态

## 📊 查询流程

```
用户输入 s/status
    ↓
遍历所有活跃任务
    ↓
对每个任务：
  1. 获取账号信息
  2. 调用 query_job(acc.base, job_id) 查询云端
  3. 获取 cloud_status 和 cloud_progress
  4. 如果与本地不一致 → 更新本地 REG
  5. 显示云端最新状态
```

## 🎯 使用方式

运行程序后：
```bash
python main.py

> s              # 查看活跃任务（实时从云端查询）
> status         # 同上
```

## 🔧 技术细节

### 核心代码位置
- **文件**: `console/app.py`
- **函数**: `show_status()`
- **API 调用**: `query_job(acc.base, t["job_id"])`

### 容错机制
- 如果云端查询失败，自动回退到显示本地状态
- 显示警告信息："查询任务 {job_id} 失败：{error}"
- 不影响程序正常运行

### 性能优化
- 只在使用 `s` 命令时查询（手动触发）
- 不增加后台轮询频率
- 查询失败不影响用户体验

## ⚡ 优势

1. **实时性**: 立即看到云端的最新状态
2. **准确性**: 数据来源是云端 API，不是本地缓存
3. **可靠性**: 查询失败时自动降级到本地数据
4. **透明度**: 明确标注"(实时从云端查询)"

## 🆚 对比

| 特性 | 之前 | 现在 |
|------|------|------|
| 数据来源 | 本地注册表 | 云端 API + 本地缓存 |
| 更新频率 | 每 5 秒 (轮询) | 每次命令触发 |
| 延迟 | 最多 5 秒 | 网络延迟 (~1 秒) |
| 准确性 | 可能滞后 | 实时准确 |
| 容错 | 总是可用 | 失败时降级 |
