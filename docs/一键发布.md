# 一键发布

把成品视频一键分发到 **抖音 / 快手 / 小红书 / 视频号** 四大短视频平台。
入口在「工具中心 → 🚀 一键发布」。

> 一期范围：**抖音 cookie 参考实现（尽量可跑通）+ 快手/小红书/视频号接口脚手架**。
> 后三个平台的真实端点/凭证后期在界面或 `config.json` 里补齐即可，不必改代码。

---

## 🎯 设计取向

- **客户端直连平台**：发布走使用者自己的平台账号，不经过任何中间服务器。
- **凭证本地加密**：Cookie / Access Token 以「使用人姓名」为密钥用 Fernet 加密，
  存本机 `config.json` 的 `publish_accounts`，**盘上不留明文、不上传服务器**。
  （与豆包 Vision 的 api_key 同一套加密逻辑。）
- **可插拔适配器**：每个平台按「鉴权方式」注册适配器，界面下拉按平台实际支持的方式过滤。
- **失败不静默**：任何一步失败都落到一条 `ok=False` 的发布记录并写日志，不中断整批。

> ⚠ 平台账号是使用者自有凭证，账号管理**不套维护人口令**（区别于素材提取的接口密钥）。

## 🧩 四平台支持矩阵

| 平台 | Cookie | 官方 OpenAPI(OAuth) | 状态 |
|------|:------:|:-------------------:|------|
| 抖音 | ✅ | — | 参考实现（web 创作者中心序列，见下方风险说明） |
| 快手 | 🔧 | 🔧 | 接口脚手架（`check_auth` 回「待配置」，`upload/publish` 抛「未配置」） |
| 小红书 | 🔧 | 🔧 | 接口脚手架 |
| 视频号 | 🔧 | 🔧 | 接口脚手架 |

脚手架的作用：让契约、账号列表、批量分支对四平台一致；后期只替换
`video_text_tools/publish/{kuaishou,xiaohongshu,tencent}.py` 的内部实现即可。

## 🖥 界面用法

1. **待发布视频**：添加一个或多个成品视频文件（仅接受视频扩展名）。
2. **共享元数据**：填标题 / 简介 / 标签（逗号或空格分隔，自动去 `#`）/ 可见性 / 封面。
   - 多文件时标题会按「`标题-文件名`」自动补区分，避免完全同名；未填标题则用文件名。
3. **发布账号**：点「＋ 添加」弹出账号对话框配置：
   - 选平台、填别名（如「主号 / 小号A」）、选鉴权方式，粘贴凭证。
   - 「🔌 检测登录」对勾选（或全部）账号跑 `check_auth`，回填登录态列。
4. 勾选要参与本次发布的账号 →「▶ 一键发布」→ 二次确认「N 条视频 × M 个账号」→ 执行。
5. 结果逐条打印在日志区（成功给 `post_url`、失败给原因），并写入发布历史表。

### 抖音 Cookie 怎么取

1. 浏览器登录 **creator.douyin.com**（抖音创作者中心）。
2. F12 → Network → 刷新 → 任选一条对该站点的请求 → 复制请求头里完整的 `Cookie:` 串。
3. 粘贴到账号对话框的 Cookie 输入框保存即可（保存后立即加密落盘）。

## ⚙️ 端点配置（`config.json` 的 `publish` 段）

抖音的可变项（端点地址 / UA / Referer / 反爬签名参数）**全部从配置读，代码不硬编码**。
默认见 `core/config.py` 的 `PUBLISH_DEFAULTS["douyin"]`：

| 键 | 含义 | 留空/占位时 |
|----|------|-------------|
| `upload_init_url` | 申请上传（POST 视频元信息 → 返回直链 + video_uri） | 空则发布时抛「端点未配置」 |
| `create_url` | 创建发布（POST 标题/简介/标签/封面 + video_uri → aweme_id） | 同上 |
| `user_info_url` | 登录态探测 | 空则 `check_auth` 跳过在线校验、不阻断发布 |
| `post_url_base` | 回执链接前缀，默认 `https://www.douyin.com/video/` | 有默认值 |
| `user_agent` / `referer` | 请求头 | 有内置默认 |
| `sign_params` | `a_bogus / msToken / verifyFp` 等反爬参数名→值 | 缺省为空 |

> 账号级可用 `extra` 覆盖以上任意键（`extra` 合并优先于全局默认），
> 便于不同账号走不同端点。发布前建议先用「🔌 检测登录」验证 cookie 有效性。

## ⚠ 抖音 web 端点的运维风险（诚实说明）

抖音一期走的是**创作者中心 web 内部端点**，这类接口：

- 会随平台改版变动（路径、字段名、返回结构都可能改）；
- 部分请求需要 `a_bogus` / `msToken` / `verifyFp` 一类反爬签名参数。

本实现把标准序列与可配置签名参数都铺好了，但**不承诺任何时点都能无条件跑通**。
若某端返回签名校验失败 / 字段变动：请在 `sign_params`、`headers` 或 `extra` 里补齐对应值，
必要时改配置即可，不必改这段业务逻辑。端点未配置（占位 `<...>`）时会明确抛「未配置」，
而不是假装成功。

## 🗂 代码结构

```
video_text_tools/publish/
  models.py     平台常量 / Account / PublishItem / PublishRecord / 异常层级
  base.py       PlatformAdapter 契约 + 注册表（register/get_adapter/supported_auth）
  douyin.py     抖音 cookie 参考实现
  _stub.py      脚手架基类（register_stub 一次注册 cookie+oauth）
  kuaishou.py / xiaohongshu.py / tencent.py   接口脚手架
  runner.py     publish_batch：视频 × 账号 矩阵、逐条容错、进度回报
  accounts.py   config 门面（list/save/delete，Account ↔ 加密 dict）
```

- 凭证读写：`core/config.py` 的 `list_publish_accounts / save_publish_account /
  delete_publish_account / publish_config`（加密沿用 `material_extract` 的
  `encrypt_value/decrypt_value`，盐=姓名，前缀 `enc:v1:`）。
- 界面：`gui/dialogs_publish.py`（`PublishPanel` + `AccountDialog`），
  经 `gui/tool_panels.py` 的 `PANEL_FACTORIES["一键发布"]` 与
  `gui/pages_tools.py` 的 `TOOLS` 卡片接线。

## 📜 发布历史在哪看

每次「视频 × 账号」的结果行都写入 SQLite `publishes` 表
（`store/publish_store.py`：`record/record_all/recent/stats`）：
字段含 `platform / account / title / video_path / ok / post_id / post_url / message / published_at`。
日志区即时显示本轮结果，历史明细可随时从该表回读。
