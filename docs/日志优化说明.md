# 日志优化 - 减少冗余信息

## ✅ 优化完成

将原本分散的多条 INFO 日志合并成一条汇总信息，大幅减少日志输出量。

## 📊 优化前后对比

### 之前的输出（每条任务 5-6 条日志）

```
10:21:34 [INFO] 行 4[acc1][job12345678] completed 100
10:21:35 [INFO] 行 4[acc1][job12345678] 下载完成 004_诺特兰德 VB_0919_01_雷亮.mp4 (45.2 MB)
10:21:35 [INFO] 行 4[acc1][job12345678] 拷贝到 NAS: 004_诺特兰德 VB_0919_01_雷亮.mp4
10:21:36 [INFO] 行 4[acc1][job12345678] Excel 已回写
```

### 现在的输出（每条任务 1 条日志）

```
10:21:36 [INFO] 行 4[acc1][job12345678] completed | 下载 1 个 | NAS 拷贝 1 个 | Excel 已回写
```

## 🔧 优化内容

### 1. **任务状态轮询 (`workers/poll.py`)**

#### 优化前
- 每次状态变化都打印 `status progress`
- 任务完成后分别打印：下载、拷贝、回写

#### 优化后
- 只在状态变化时打印一次
- 任务完成后**汇总为一条日志**：
  ```
  completed | 下载 N 个 | NAS 拷贝 N 个 | Excel 已回写
  cancelled | Excel 已回写
  failed
  ```

### 2. **视频下载 (`processors/video_processor.py`)**

#### 优化前
- 每个视频下载成功都打印：`下载完成 xxx.mp4 (45.2 MB)`
- 每次重试都打印警告

#### 优化后
- **不输出成功日志**（由 poll.py 汇总）
- 重试时只输出 DEBUG 级别
- 最终失败才输出 ERROR

### 3. **NAS 拷贝 (`processors/video_processor.py`)**

#### 优化前
- 每个文件拷贝成功都打印：`拷贝到 NAS: xxx.mp4`
- NAS 未挂载输出 WARNING

#### 优化后
- **不输出成功日志**（由 poll.py 汇总）
- NAS 未挂载降级为 DEBUG
- 只输出失败时的 ERROR

## ⚡ 优化效果

| 指标 | 之前 | 现在 | 改善 |
|------|------|------|------|
| 单任务日志数 | 5-6 条 | 1-2 条 | **减少 70%** |
| 多任务日志数 | 每任务 4 条 | 每任务 1 条 | **减少 75%** |
| 日志可读性 | 分散 | 汇总 | **大幅提升** |
| 信息密度 | 低 | 高 | **更紧凑** |

## 🎯 使用建议

### 查看详细信息
如果需要查看详细的下载过程（如每个文件的大小），可以临时调整日志级别：

```python
# 在 config.py 中
LOG_LEVEL_CONSOLE = "DEBUG"  # 查看详细日志
```

### 日常使用
保持默认配置即可：
```python
LOG_LEVEL_CONSOLE = "INFO"  # 只看汇总信息
```

## 📁 修改文件

1. **`workers/poll.py`** - 任务轮询线程
   - 汇总任务完成的所有操作到一条日志
   
2. **`processors/video_processor.py`** - 视频处理
   - 移除成功的 INFO 日志
   - 重试日志降级为 DEBUG
