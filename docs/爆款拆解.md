# 爆款拆解

粘贴一条抖音/快手爆款视频的分享链接，软件自动完成：**解析下载去水印视频 → 画面分析（整条视频一次传豆包直连，或传统本地抽帧+逐帧分析，二选一） → 口播转写 → 生成 3 类提示词 + 整体分析 → 导出 Word 拆解文档 → 抽「图集 + 封面」入拆解任务库**。

拆解结果会存进**拆解任务库**，可随时打开「图集 | 播放器 | 拆解文档」三屏联动详情页回看（不依赖重新解析）。

入口：工具中心 → **爆款拆解**（🔥）。

---

## 1. 安装与依赖

基础安装沿用主程序，不额外装东西就能用「画面拆解 + 提示词 + 整体分析」。

**可选：口播逐字稿（Whisper 转写）** 需要 faster-whisper，它体量大、不打进主 exe，按需安装（开发版）：

```bash
pip install -r requirements-breakdown.txt
```

没装也能拆——只是「转写」阶段会被明确标为跳过，画面拆解与提示词照常产出。

---

## 2. 豆包 Vision 配置（画面分析必需）

逐帧画面分析走**火山方舟 Ark** 的 OpenAI 兼容端点。豆包凭证的编辑已**统一收口到「🔌 接口管理」页**
（面板里只留「✅/⚠ 豆包状态」与「🔌 去接口管理配置」跳转；该页默认藏起来，在「⚙️ 设置」按维护人口令
`Alt+W` 解锁后出现）。在那里填 api_key / 端点 ID / Base URL，**保存即生效、不用重启**。配置步骤：

1. 注册火山方舟，新用户送 500 万 token 免费额度；参加**「协作奖励计划」每天调用可得免费额度**；
2. 在「开通管理」里选一个**视觉理解模型**（如 **Doubao-Seed-1.6-Vision**，名称里带 **Vision** 的才行）；
3. 在「推理接入点」创建并复制**接入点 ID**（形如 **`ep-xxxxxxxx`**），填到「端点 ID」；
4. 在「API Key 管理」生成 **API Key**，填到「API Key」。

- **Base URL** 默认 `https://ark.cn-beijing.volces.com/api/v3`，一般不用改。
- **api_key 以你的使用人姓名（`USER_NAME`）为盐 Fernet 加密后写入 `config.json` 的 `doubao_vision` 段，盘上不留明文**；换机器/换名解不开即视为未配置。
- 提示词生成 / 整体分析 / 改写去重都复用**同一个**豆包接入点，不引入第二个模型服务。

## 3. Whisper 模型下载（转写用）

模型**只下不打包**，默认下到 `%APPDATA%\AIGC视频助手\models\`。

- 下载在「🔥 爆款拆解」面板可选档 + 查看就绪状态；**模型本体下载已可在工具中心「🎙 语音识别」里就地完成**（进度走悬浮球，无需去别处），
  接口管理页也保留逐档下载入口；
- 勾选**「用国内镜像」**走 `hf-mirror.com`，官方源连不上时用它（大文件走直链续传、有真实进度）；
- 面板「Whisper 模型」下拉**默认取已就绪的最佳档**（`best_ready_size`），不再写死未下载的 medium，
  免得一进面板就催你下载；
- **手动放置**：把 faster-whisper 的 CTranslate2 模型目录放到
  `...\models\models--Systran--faster-whisper-<size>\`（含 `blobs/` 文件）即可被识别为就绪。

未就绪时点「开始拆解」不会卡死——「转写」阶段被标注失败原因，其余阶段继续。

## 4. 使用流程

1. 粘贴分享文案/链接（一次拆一条，取第一条能解析出视频的）；
2. 选项：**Whisper 模型**、**视觉方式**（`video_url 直连`（默认）/ `逐帧抽取`，见下节）、**抽帧密度 fps**（仅直连模式）、**抽帧间隔**（仅逐帧模式，默认 3 秒）、**视觉并发**（默认 1、≤ 3，仅逐帧模式，防限流）、**视频存到**（输出目录）、**✨ DeepSeek 语义纠错**（识别后先改同音字再送豆包拆解；未配置则置灰不可勾）；
3. 「▶ 开始拆解」——进度条 + 左侧阶段状态列表实时显示每一步 ✅/❌（直连模式下本地 Whisper 转写与豆包画面解析**并行**执行、两者互不依赖，逐帧模式仍串行）；
4. 完成后右侧预览分镜表、3 类提示词、整体分析；
5. 完成后自动：**导出 Word 拆解文档**（落在视频所在目录、与视频同名 `.docx`）→ 按分镜时间戳抽**图集 + 封面**存进**拆解任务库** → 入库。点「🔎 打开详情页」进入「图集 \| 播放器 \| 拆解文档」三屏联动；面板右侧「拆解任务」列与左侧导航「🔥 拆解任务」管理页都能随时回看。

> 解析视频**复用「素材提取」的聚客解析接口**（抖音链 → 去水印视频直链 → 下载），需在素材提取里配好接口与直链域名白名单。不引入 Playwright。

## 5. 两种画面分析模式

### video_url 直连（默认，推荐）

把**本地已下载的视频**经方舟 **Files API** 上传（`purpose=user_data` + `preprocess_configs[video][fps]`），轮询到文件 `status=active` 拿到 `file_id`，再用 `{"type":"video_url","video_url":{"file_id":"…","fps":0.5}}` **一次调用**整条视频，模型自己抽帧+音画理解，**一条视频只需 1 次视觉调用**；本地仍下载视频（Whisper 转写需要），但**不再执行抽帧与逐帧上传**。

- **为什么走 Files API、不直接传公网直链**：公网直链有防盗链/时效，豆包后端常取不到 → 秒失败回退（实测踩过）；Files API 上传本地文件不依赖外网可达，且**上限从 50MB 提到 512MB**（默认托管存储，存 7 天可复用）；
- **为什么能降 429**：46 秒视频逐帧要 15+ 次带图请求，实测极易连坐触发方舟限流；直连视觉阶段从几十次降到 1 次；
- **fps 取舍**：官方范围 [0.2, 5]，默认 0.5——越高分镜越细但 token 越贵、耗时越长；上传时即写入 `preprocess_configs`，短视频拆解 0.3~1.0 够用；
- **自动回退，不会因直连而新增崩点**：本地文件缺失 / >512MB → 执行前就改走逐帧链路并在日志/备注说明原因；上传或直连调用失败（如预处理报错、超时）→ 自动补跑完整「抽帧+逐帧」旧链路。两种模式输出字段完全一致，下游提示词/Excel 列不受影响。

### 逐帧抽取（传统兜底）

本地 ffmpeg 按**抽帧间隔+场景切换**提关键帧，逐帧以 base64 图片传豆包分析。**并发默认 1 + 帧间 sleep 1.5s**（每帧含图上传，高并发实测秒撞免费账号 QPS 上限）；面板可调 1~3，宁慢不崩。适合直连不可用或需要本地帧图复查的场景。

## 6. Word 拆解文档包含的内容

拆解成功后自动生成一份 `.docx`，落在视频所在目录、与视频同名（如 `骨胶原-9.27-142_11.mp4` → 同名 `.docx`），含以下区块：

| 区块 | 内容 |
| --- | --- |
| 概览 | 标题 / 参考链接 / 时长 / 分镜数 / 豆包用量（次数・token） |
| 一、整体分析 | 前 3 秒钩子 + 评分（0-10）、爆点因素、情绪曲线、内容公式、复刻蓝图 |
| 二、口播逐字稿 | Whisper 转写全文（逐句带起始秒数） |
| 三、分镜画面表 | 逐分镜的景别/运镜/构图/转场/画面文字/情绪 |
| 四、三类复刻提示词 | 每分镜的画面生成 / 文案改写（已改写去重）/ 复刻拍摄清单 |

空字段自动跳过，哪怕只解析出部分内容也能出一份完整文档。（旧版“回写任务表 12 列”的 Excel 交付已废止——Excel 可读性差、拆一条塞一行不便看。）

## 7. 失败与半成品处理

- 任一阶段失败都在**面板**（阶段状态 ❌ + 原因）和**日志/备注**（如「转写失败：…」「画面分析失败：…」）**明确标注，绝不静默**；
- **能降级的继续降级**：没装 faster-whisper / 模型没下 → 转写标注跳过，画面拆解与提示词照出（需导出 Word 则额外装 python-docx）；
- **半成品不导出 Word，但仍入库**：解析失败或有阶段失败时不生成 Word 文档，但会把已有产物（如仅转写、仅部分分镜）连同图集一并存进任务库并标「未完成」；在详情页/管理页卡片上会带红色 ⚠ 角标，可回看已拆出的部分、定位问题后重跑。

---

## 8. 成本统计

拆解完成后日志给出**豆包调用次数**与**累计 token**。直连模式视觉阶段只计 1 次（另有 1 次 Files API 上传）；逐帧模式 = 帧数次带图请求；两种模式都另加文本生成/整体分析/改写次数。429 走分钟级全局冷却重试、5xx 自动指数退避。

> ⚠ **方舟额度提醒**：新用户若开着「安全体验模式」，用量上限极低，几轮逐帧调试就会打满 → 此后**所有请求**（哪怕极小文本）秒回 `429 SetLimitExceeded`、模型服务被暂停，冷却重试永远等不回来。本软件对此**快速失败**并把控制台自助恢复路径（到「模型开通/限额管理」调高上限或关闭安全体验模式）写进日志/阶段状态，不再白等。

---

## 9. 合规约束

- 只做**内容拆解与可复用提示词生成**，不直连平台发布 API、不自动搜索对标账号、不做 GMV 推断；
- 拆解结果经 **AI 改写/去重**（「改写去重」阶段）后再落列，尽量规避平台查重与版权风险；
- 拆解的**工作帧/临时下载**（逐帧模式的中间帧、音频）跑完即清理；但任务库的**图集与封面**是交付的一部分，持久保存在 `outputs/爆款拆解/任务库`，删任务只删记录、不删图；是否保留成品视频由「视频存到」目录决定。

## 10. 拆解任务库与三屏联动详情

拆解跑完后，结果不再只是一次性预览——它会**持久化成一个「任务」**，跨会话可回看。

### 两个入口（同一份库）
- **拆解面板右列**：每次拆完自动刷新，封面小图 + 标题，双击即开详情；顶部「🗂 打开任务管理」跳管理页。
- **左侧导航「🔥 拆解任务」管理页**：卡片墙（封面缩略图 / 标题 / 分镜数·时长 / 状态角标），支持按标题搜索、右键删除、打开任务库目录。

每个任务在库里是一行 SQLite（`breakdown_tasks` 表，`payload` 存整个 `BreakdownResult` 的 JSON），图片落 `BREAKDOWN_LIBRARY`（`…\outputs\爆款拆解\任务库\{时间戳}_{视频名}\`，含 `cover.jpg` + `gallery/f*.jpg`）。

### 详情页 = 三屏并排（图集 | 播放器 | 拆解文档）
| 屏 | 内容 |
| --- | --- |
| 左·图集 | 上方当前大图，下方按分镜时间戳抽的缩略图竖排；点缩略图跳到该分镜时刻 |
| 中·播放器 | 内嵌视频播放器（播放/暂停 + 进度条 + 时间标签），视频被移动/删除时给占位提示，图集与文档仍可看 |
| 右·拆解文档 | **分镜轴** + **逐字稿轴**两个可点列表，每条带时间戳；顶部另有打开 Word / 定位视频入口 |

### 双向联动规则
- 点**分镜**或**逐字稿**任一条时间戳 → 视频跳到该秒 + 图集切到对应帧 + 该条高亮；
- 视频**播放推进** → 反算当前分镜/当前口播句 → 文档对应条高亮 + 图集自动换图（位置更新经节流，避免高频重绘）；
- 图集与两条轴的对齐统一走纯函数「取最后一个 `<=当前秒` 的分镜帧」，所以 seek 到某句口播时图集停在最贴近的分镜画面。

联动的时间轴与索引逻辑都在无 Qt 的 `video_text_tools/breakdown/timeline.py`（`build_timeline` / `index_at`），抽帧在 `gallery.py`（`build_gallery`），入库在 `store/breakdown_store.py`——GUI 只做装配，核心均可单测。

## 11. 打包说明

`AIGC视频助手.spec` 的 `excludes` 已排除 `faster_whisper / ctranslate2 / tokenizers / av`（转写重依赖）与 `scipy / matplotlib / IPython / notebook / tkinter`（无用大件），控制体积 < 300MB。要出「含转写」的包见 spec 顶部注释。导出 Word 依赖 `python-docx`（仅带 lxml，本体很轻），两个 spec 都已 `collect_data_files('docx')` 把默认样式模板一并打包，因此**精简版也能导出 Word**（只是精简版不带转写）。
