# 语音识别（主体模块 + 工具中心「🎙 语音识别」）

**语音识别是这条链路的主体能力**：选视频 → faster-whisper 转口播逐字稿 →（可选）DeepSeek
按语义改同音字 → 产出逐字稿 `.txt` / 字幕 `.srt`，或直接把字幕**烧录**进画面。
「录屏字幕」和「爆款拆解」都不是各自再造一套识别，而是**复用同一个语音识别主体**——
它们只是这套识别的不同消费者。

入口：**工具中心 → 🎙 语音识别**。就地选视频、就地下载模型、勾选产出方式，一键跑。

---

## 1. 为什么要独立成一个工具

字幕烧录/导出、爆款拆解早就在用语音识别了，但工具中心里**没有一处能直接「只转文字、
只出字幕」**的地方——想拿一段视频的口播逐字稿，要么绕录屏字幕、要么绕拆解。现在把主体
能力直接上架：**打开语音识别工具 → 选视频 → 开始识别**，产出逐字稿/SRT/烧录，不必依赖
任何隐藏页。

- **模型就地下载**：面板顶部的模型条（ModelBar）自带「⬇ 下载模型」，进度走悬浮球，
  未就绪时会说「点右侧『⬇ 下载模型』就地下载，无需去别处配置」——**不再弹窗教用户去
  哪、按什么快捷键、用什么口令**。
- **DeepSeek 纠错只留开关**：勾「✨ DeepSeek 语义纠错」即可；没配好端点时该选项**置灰 +
  tooltip 说明**（去「🔌 接口管理」填 key/model 后回来就能勾），**绝不弹窗、绝不拦截**。
  配置本身仍统一收在接口管理页（见「语音纠错」说明）。

## 2. 界面用法

1. 工具中心点 **🎙 语音识别**；
2. 「视频文件（可批量）」添加待识别的视频；
3. 模型条选档（默认已就绪的最佳档），未就绪点「⬇ 下载模型」（慢/连不上勾「用国内镜像」）；
4. 「输出」区勾选要产什么：
   - ☑ **保存逐字稿 `.txt`**（一行一句纯文字稿）
   - ☑ **导出字幕 `.srt`**（带时间戳，可导剪映/播放器）
   - ☐ **✨ DeepSeek 语义纠错**（需已配置，未配置置灰）
   - ☐ **烧录字幕到画面**（另存 `_字幕.mp4`，需 ffmpeg 带 libass）
5. （可选）指定输出目录，留空＝各视频同目录；
6. 「▶ 开始识别」；完成后第一条逐字稿显示在预览区，日志汇总「成功 X / 共 N，已产出文件 Y 条」。

> 至少勾一种输出（逐字稿 / SRT / 烧录），否则点开始会提示先选。

## 3. 代码结构（语音识别主体）

识别本体从原来散落在 `breakdown/` 里，抽成独立主体包 `video_text_tools/asr/`：

```
video_text_tools/asr/
  __init__.py   对外门面：暴露子模块 types / transcribe / fixer，并 re-export
                异常与数据类型 + apply_fix（消费者统一从 asr 拿）
  types.py      单一来源：TranscriptSegment / TranscriptWord +
                AsrError/TranscribeError/DepMissing/ModelNotReady/FixError/FixNotConfigured
  transcribe.py 模型管理（就绪判定 best_ready_size / model_ready / download_model_auto /
                镜像多端点兜底）+ 转写 transcribe / transcribe_stream + to_srt
  fixer.py      AsrFixer.correct_segments（编号行发、按编号回填、失败退原文）
                + apply_fix(segments, glossary, cfg, chunk) → (changed, cost, note)：
                  统一纠错入口，**绝不抛**——未配置/初始化失败/某块失败都保留原文并回一句 note
```

- `video_text_tools/breakdown/models.py` 只做 **re-export**（`from ..asr.types import ...`），
  异常/类型仍与 asr 是**同一批对象**（`is` 判定一致），老 `from breakdown.models import X` 不断链。
- 消费者都改指向主体：`from ..asr import transcribe as tr` / `from ..asr.fixer import apply_fix`。

## 4. 三个消费者怎么用同一个主体

| 消费方 | 入口 | 用识别做什么 | 纠错 |
|--------|------|--------------|------|
| **语音识别** | 工具中心 🎙 | 转写 → TXT/SRT/烧录（本体） | 勾选 `asr_fix` → `engine` 调 `apply_fix` |
| **录屏字幕** | 屏幕录制 / 任务中心 🔤 | 转写 → SRT/ASS → 烧录 | `SubtitleOptions.asr_fix`（默认关） |
| **爆款拆解** | 工具中心 🔥 | 转写口播 → 送豆包分镜拆解 | 勾选 ✨ 纠错 → `pipeline` 调 `apply_fix`（opt-in） |

三者共用同一套 Whisper 依赖与模型目录（`%APPDATA%\AIGC视频助手\models`），**模型下一次三处共享**。

## 5. 关键约定

- **纠错/字幕默认关**：`SubtitleOptions.asr_fix / save_txt` 默认 `False`，不擅自联网、不多产文件。
- **失败不静默**：`apply_fix` 任何异常都保留原始识别、回一句说明（写进结果 `message`/`notes`），
  绝不把原文当「已纠正」骗人；识别缺库/缺模型按 `DepMissing`/`ModelNotReady` 归类给引导动作。
- **不新增重依赖**：Whisper 走既有可选包 `requirements-breakdown.txt`，烧录用既有 ffmpeg，不改打包 spec。
- **不弹教学框**：任何「去哪配置 / 按什么快捷键 / 用什么口令」的提示都不做——
  模型就地下载、纠错未配置只置灰给 tooltip。
