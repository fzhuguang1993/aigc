# 云端接口字段说明（实测核对，非推测）

> 核对方式：`GET {base}/openapi.json`（FastAPI 自带）+ 真实作业回报。
> 随时可用 `python test/check_payload_fields.py` 重新对一遍，不提交任务、不占额度。

## 1. 最重要的一条：请求体是严格模型

`JobRequest` / `JobInputs` / `JobParameters` 三层的
`additionalProperties` 全部是 `false`——**多写一个字段，整单 HTTP 422 被拒**，
不是"忽略这个字段"。

已经踩过的坑：把生成步数写成 `parameters.steps`，结果是**每一条线路、每一个任务
都提交失败**，而界面上只有一行转瞬即逝的灰字，看起来像"改了参数没生效"
（取消过的任务重新提交也是同一条失败路径）。步数的正确字段名是 **`inference_steps`**。

422 报文长这样（真实抓取）：

```json
{"error": {"code": "validation_error", "message": "The request parameters are invalid.",
  "details": {"errors": [{"type": "extra_forbidden",
                          "loc": ["body", "parameters", "steps"],
                          "msg": "Extra inputs are not permitted", "input": 8}]}}}
```

`workers/submit.py` 会解析 `loc`，把被拒字段从 payload 里摘掉后**在同一条线重试**
（`type` 只认 `extra_forbidden`，取值非法类错误不能摘字段），摘不掉就直接失败并把
"云端拒绝参数：parameters.xxx"递到界面——**不再逐条线路退避重试**（参数写错时换线毫无意义）。

## 2. `parameters` 全部可用字段

| 字段 | 类型 / 取值 | 默认 | 说明 |
|------|------------|------|------|
| `width` | int 256–2160 | 1344 | 我们固定 768 |
| `height` | int 256–2160 | 768 | 我们固定 1376（竖版） |
| `duration` | number 2–15 | 5 | 视频秒数，对应工具栏「时长」 |
| `inference_steps` | int 1–50 或 null | — | 生成步数，对应工具栏「步数」 |
| `quality_mode` | `ultra` / `balanced` / `fast` | balanced | **暂未接入界面** |
| `model_mode` | `high_quality` / `low_memory` / `custom_model` | high_quality | 显存不够时用 low_memory |
| `main_model` | str 或 null | — | 配合 custom_model 指定主模型 |
| `seed` | int | -1 | -1 = 随机（抽卡就靠它） |
| `upscale_enabled` / `upscale_mode` / `upscale_scale` | bool / `tiny-long`\|`full` / 2\|3\|4 | false | 放大 |
| `frame_interpolation_enabled` / `_multiplier` | bool / int 2–100 | false | 补帧 |
| `audio_drive_enabled` | bool | false | 音频驱动 |
| `ref_image_size` | `match` / `720p` / `native` | match | 参考图处理方式 |
| `avatar_audio_mode` / `avatar_style` | — | — | avatar 模式专用 |
| `fixed_character_shot` | bool | false | 固定人物镜头 |
| `loras` | `[{name, strength}]`，strength 0–2 | — | 元素也是严格模型，只认这两个键 |

`inputs` 可用字段：`prompt`、`first_frame`、`last_frame`、`reference_images`（≤9）、
`reference_videos`（≤3）、`reference_audios`（≤3）、`storyboard_id`、`avatar_image`、
`driving_audio`、`voice_reference_audio`、`dialogue_language`、`dialogue_text`（≤200 字）。

`mode` 可选：`t2v` / `i2v` / `r2v` / `video_replace` / `avatar` / `avatar_long`；
`feature` 固定 `minimax-h3`。

## 3. 状态与负载查询

- `GET {base}/jobs?limit=N`（limit 上限 200）返回 `{"items": [...]}`，
  每项含 `job_id / status / progress / position / submitted_at / started_at /
  completed_at / mode / prompt / width / height / duration / model / steps / seed /
  current_node / error`。
- 实测出现过的 `status`：`completed`、`cancelled`（**一个 l**）、`running`。
  代码里判断"是否还占着线路"用 `registry/manager.py: is_active()`——
  **排除终态**，不枚举活跃态，云端冒出新的排队词也不会漏。
- 一次抓 541 条作业统计：`position` 全为 null（排队时是否会有值未经证实），
  所以负载仍按"数非终态作业"算。
- 作业的 `duration` 回报里有 18.4 / 28.6 这类超过 15 秒的值——那是分镜
  （`video_replace` + storyboard）多段合并后的成品长度，**不代表可以请求超过 15 秒**。

## 4. 其他可用接口（暂未接入）

`GET /api/v1/capabilities`：这台云端实际支持哪些 feature/mode/主模型/lora 清单
（我们硬编码的 `minimax_h3_ref2v_turbo_8step...` 就在它的 loras 列表里）。
换线路或云端升级时，这个接口能提前告诉你"这个 lora 还在不在"。

`POST /api/v1/jobs/batch`、`GET /api/v1/jobs/{id}/segments`、
`POST /api/v1/jobs/{id}/segments/{i}/regenerate`（单镜重生成）、
`.../segments/clean-black-frames`（去黑帧）、`POST /api/v1/storyboards`。
