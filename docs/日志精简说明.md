# 日志进一步优化 - 精简输出

## ✅ 优化完成

针对用户反馈的"提示很臃肿"问题，进一步优化日志输出，减少冗余信息。

## 🎯 主要改进

### 1. **提交任务时不再显示口播提取结果**

#### 优化前
```
11:55:36 [INFO] [行 34][acc1][-] 上传参考图 诺特兰德益生菌.png -> quickstudio_asset_e42442bff513.png
11:55:36 [INFO] [行 34][acc1][8c90f1e2] 提交成功
11:55:37 [WARNING] [行 34][acc1][-] 未找到可提取的口播文案
   第 34 行提交成功 [acc1] job_id = 8c90f1e2-1890-4e92-8a12-fbfeb4091c06
   口播文案提取失败
```

#### 优化后
```
   第 34 行提交成功 [acc1]
```

**改进点：**
- ✅ 移除 `job_id` 完整显示（太长）
- ✅ 移除口播提取成功/失败的提示（避免冗余）
- ✅ 口播提取改为后台静默执行

### 2. **上传参考图日志降级为 DEBUG**

#### 优化前
```
11:55:36 [INFO] [行 34][acc1][-] 上传参考图 诺特兰德益生菌.png -> quickstudio_asset_e42442bff513.png
```

#### 优化后
```
（不显示，降级为 DEBUG 级别）
```

**改进点：**
- ✅ 上传过程改为 DEBUG 级别
- ✅ 只在需要调试时才查看详细上传日志

### 3. **空镜任务静默处理**

对于没有口播的空镜任务（如你的新项目），不再输出 WARNING 警告。

**原因：**
- 空镜任务本来就没有对话
- 提取失败是正常的，不是错误
- 避免误导用户以为有问题

## 🔧 修改内容

### 1. **`console/app.py`** - `run_one_row()` 函数

```python
# 之前
if success:
    print(f"  ✓ 口播文案已提取并保存")
else:
    print(f"  ⚠ 口播文案提取失败")

# 现在
# 异步提取口播文案（不阻塞，不输出失败信息）
extractor.extract_and_save(row_idx, prompt, ...)
```

**改进：**
- 移除口播提取结果的打印
- 改为后台静默执行
- 只保留提交成功的核心信息

### 2. **`processors/script_extractor.py`** - `extract()` 方法

```python
# 之前
if not script:
    error = "未找到可提取的口播文案"
    ctx.warning(error)
    return None, error

# 现在
if not script:
    # 空镜任务没有口播，不输出警告（静默处理）
    return None, None
```

**改进：**
- 空镜任务不再输出 WARNING
- 静默返回 None
- 避免误导用户

### 3. **`workers/submit.py`** - `build_payload()` 函数

```python
# 之前
ctx.info(f"上传参考图 {p.name} -> {aid}")

# 现在
ctx.debug(f"上传参考图 {p.name} -> {aid[:20]}...")
```

**改进：**
- 上传日志降级为 DEBUG
- 只显示 ID 前 20 个字符（更简洁）
- 日常使用不显示

## 🎯 使用建议

### 查看详细日志（调试模式）

如果需要查看详细的上传过程或提取细节，可以临时调整日志级别：

```python
# 在 config.py 中
LOG_LEVEL_CONSOLE = "DEBUG"  # 查看详细日志
```

### 日常使用

保持默认配置即可：
```python
LOG_LEVEL_CONSOLE = "INFO"  # 只看关键信息
```
